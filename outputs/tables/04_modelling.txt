==============================================================================
4. BASELINES
==============================================================================

  A model is only good relative to something. Three reference points,
  all scored on the SAME test set later in this run.

  1. Random          -> PR-AUC = the base rate by construction
  2. Heuristic       -> rank by total_relationship_count, ascending
                        (fewer products held = higher churn risk). This
                        is what an analyst produces with one SQL query.
  3. Logistic        -> interpretable, regularised


==============================================================================
5. CALIBRATION (fitted on validation)
==============================================================================

  The profit model in stage 6 multiplies by P(churn) as a probability,
  so being correctly ranked is not enough -- the number has to mean what
  it says. Both isotonic and sigmoid (Platt) are fitted on validation.

  ACCEPTANCE RULE (all judged on validation; test is not consulted):
    1. It must improve validation Brier by at least 0.002. Anything
       smaller is not worth an extra moving part.
    2. It must not reduce validation PR-AUC. A calibrator that damages
       ranking is taking away the thing the policy layer runs on.
    3. It must leave at least 100 distinct scores. Stage 6 targets the
       top-k customers by score; a calibrator that collapses the range
       into a handful of levels makes 'the top 250' undefined.

  Rule 3 is the operational one and it is easy to overlook: isotonic
  regression is a step function, so it maps many scores onto one value.

  logistic_strict
    variant       val Brier     gain  val PR-AUC  distinct  accepted
    raw              0.1320        -      0.2233     2,026         -
    isotonic         0.1301  +0.0019      0.2335        12     False
    sigmoid          0.1319  +0.0000      0.2233     2,026     False
    -> none (raw model kept)

  lightgbm_strict
    variant       val Brier     gain  val PR-AUC  distinct  accepted
    raw              0.1292        -      0.2632     2,019         -
    isotonic         0.1277  +0.0015      0.2597        15     False
    sigmoid          0.1292  +0.0000      0.2632     2,019     False
    -> none (raw model kept)

  logistic_all
    variant       val Brier     gain  val PR-AUC  distinct  accepted
    raw              0.0670        -      0.7824     2,026         -
    isotonic         0.0646  +0.0024      0.7733        24     False
    sigmoid          0.0666  +0.0003      0.7824     2,026     False
    -> none (raw model kept)

  lightgbm_all
    variant       val Brier     gain  val PR-AUC  distinct  accepted
    raw              0.0300        -      0.9617     2,026         -
    isotonic         0.0243  +0.0057      0.9596        20     False
    sigmoid          0.0256  +0.0045      0.9617     2,026      True
    -> sigmoid

  Raw model kept for : logistic_strict, lightgbm_strict, logistic_all
  Calibrator applied : lightgbm_all -> sigmoid

  Isotonic is rejected everywhere, always on rule 3: it collapses ~2,000
  scores into 12-24 levels. Sigmoid is rejected wherever the Brier gain
  is below the 0.002 threshold, which is every model except the
  all-features LightGBM, where it gains 0.0045 and is accepted.

  The RECOMMENDED model (lightgbm_strict) keeps its raw scores. That is
  not a cop-out: LightGBM trained without class reweighting is already
  close to calibrated, which is precisely why class_weight='balanced'
  was rejected in src/train.py. The Brier gain on offer was 0.0015, and
  isotonic wanted to collapse 2,019 distinct scores into 15 to get it.
  For a model whose whole job is to rank customers for targeting, that
  is a bad trade.
